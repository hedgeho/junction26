# Reader quality audit - November 15, 2026

## Results

- 250 package regression tests passed across core, ingestion, curation and web.
- 19 browser scenario groups passed with zero uncaught browser errors.
- Ruff lint, Ruff formatting and JavaScript syntax checks passed.
- Live Gemini Decisions, Gemma profile editing, request scoring, per-note matching and final selection returned valid outputs.
- The shared Drive test folder imported one Markdown file through Context.dev. Its original chunk reached Gemma matching; an unrelated post correctly produced no match.
- The Modal model endpoint rejected an unauthenticated request with HTTP 401.

These checks cover defined scenarios, not every possible provider response or production load. Social publishing was simulated rather than creating real likes, replies or reposts on the user's account. Existing backend tests exercise provider contracts and authorization. The browser audit does not exercise a fresh interactive OAuth login.

## Browser coverage

The audit uses an isolated copy of existing real local posts. It blocks remote social writes at the test server and intercepts browser mutations; it never adds placeholder posts to the running application.

| Area | Checks |
| --- | --- |
| Feed | Real source posts, source metadata bootstrap, daily limit validation, immediate hard cap |
| Feedback | Independent post drafts, correct post/feed context, asynchronous race handling, duplicate prevention, failure recovery |
| Intentional discovery | Both Tell your feed and Show more, Ctrl+Enter, full-feed context, no automatic reload over unfinished writing |
| Social actions | Like/save state and undo, direct/quote repost outlines, contextual composers, own reply display, deletion, canonical sharing |
| Threads | Incremental reply batches, nested replies and their interaction controls, six levels at 320px width |
| Notes | Excerpts appear after the feed, remain literal text, update after the first matching pass and disappear when removed |
| Settings | Multiple notes links, processing disclosure and privacy link, Threads coming soon, configuration discovery |
| Revisions | Configuration edit, visible literal changes, restore, exact original Markdown download |
| Presentation | Desktop, tablet, phone, 320px width, in-place image overlay, Escape/focus return, theme persistence |
| Failure handling | Provider errors retain drafts and restore controls; no uncaught browser errors |

## Repeatable checks

```sh
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
node --check packages/web/src/curator_web/static/app.js
uv run --with playwright python scripts/check_reader_ui.py
uv run curator-curate check-providers
```

The browser command requires at least ten real posts in the local reader database and Microsoft Edge on Windows or Playwright Chromium elsewhere. It starts a temporary loopback server, copies state into a temporary directory, and shuts the server down on completion. Screenshots and the scenario report are written to ignored `data/ui-audit/`. Provider checks require configured credentials and make live model calls. The Drive import check was a separate read-only integration probe and is not part of the browser runner.

## Important fixes

- Feedback drafts, idempotency keys and status are scoped to the individual post or whole feed, so switching context during a request cannot overwrite another draft.
- New feed selections wait for open editors, pending feedback and unsent drafts before refreshing.
- Social composers retain drafts per target and prevent duplicate submissions while posting.
- Imported author/media metadata is rendered immediately; replies also support images and external previews.
- Polling pauses on hidden pages, backs off on failures and stops on terminal session errors. Notes continue checking at a slower cadence after their initial completion.
- One-time Show more instructions use Gemma even when ordinary filtering uses Gemini Decisions, with separate score versions and the correct relevance scale.
- Feed and note-matching configuration each retain their own visible history. Restoring preserves the original Unicode and line endings.
